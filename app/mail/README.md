# Почта

## Приём через IMAP

Вызов `poll_once(settings, store.receive_mail, cursor=cursor)` читает `INBOX` в режиме read-only через SSL, сохраняет сообщения через общий интерфейс и возвращает следующий курсор. Храните курсор отдельно для каждой привязки и сохраняйте его после успешного возврата. Повтор с прежним курсором использует дедупликацию входа по ящику, папке, UIDVALIDITY и UID. Из асинхронного сервиса вызывайте poll через `asyncio.to_thread`.

Первый вызов с пустым курсором и без `initial_after_uid` начинает с конца папки. Для ограниченного импорта оператор передаёт заранее выбранную нижнюю границу `initial_after_uid`. После `MailboxGenerationChanged` опрос останавливается. Проверьте ограниченное окно новой папки относительно входящих событий и доставок, затем явно задайте новую границу. Автоматический повтор прежних доставок при смене поколения исключён.

По умолчанию один вызов обрабатывает до 25 писем и принимает письмо размером до 2 МБ. Вложения не сохраняются. Письмо с превышением лимита, с неподдерживаемым MIME или с ошибкой разбора останавливает продвижение курсора и требует операторского решения.

## Маршрутизация и оценка

`classify_mail(mail, context, model=...)` принимает нормализованное письмо и настройки профиля. `route_mail(candidate, context)` применяет профильные маршруты, разрешённых получателей и флаги автоматизации. Календарный маршрут требует явного правила и передаётся на проверку доступности в общем сценарии. Чувствительные и неоднозначные письма требуют согласования. `sender_policy` должен поступать из доверенной настройки, поскольку заголовок From сам по себе не подтверждает полномочия.

`python -m app.mail.evaluate --input private.csv` печатает JSON-отчёт без подключения к почте и модели. CSV содержит `id`, `text`, `expected_action` или `expected_route`. Дополнительно поддерживаются `subject`, `from` и `expected_policy_class`. Для проверки профиля, где КП уходит на согласование, добавьте `--quote-route review`.

## Отправка через SMTP

`SmtpEmailTransport(settings, store=store)` реализует `EffectTransport`. Используйте профильный набор разрешённых получателей. Для производственного исполнителя включите `require_recipient_fingerprint=True` и сохраняйте `recipient_fingerprint(address)` в эффекте из доверенной настройки версии.

Исходы `sent`, `retryable`, `failed` и `unknown` различают приём сервером, временный отказ, окончательный отказ и возможный приём без ответа. Не повторяйте `unknown` до сверки с провайдером. Один эффект соответствует одному получателю и одному Message-ID.

Переменные окружения для ручной проверки и стандартной конфигурации: `YANDEX_MAIL_ADDRESS`, `YANDEX_MAIL_APP_PASSWORD`, `MAIL_RECIPIENTS` (JSON `{"ссылка": "адрес"}`), необязательно `SMTP_HOST` (smtp.yandex.ru), `SMTP_PORT` (465), `SMTP_TIMEOUT_SECONDS` (20).

Команда живой проверки `python -m app.mail --to you@example.com` отправляет одно сообщение. Используйте выделенный стендовый ящик и заранее согласованный адрес.
