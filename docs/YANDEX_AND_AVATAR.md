# Яндекс ID, внешние API и живой аватар

[К командному плану](TEAM_PLAN.md)

## 1. Завести отдельный Яндекс ID для стенда

1. Назначьте владельца тестового аккаунта и резервного ответственного за стенд. Владелец проходит [полную регистрацию Яндекс ID](https://yandex.ru/support/id/ru/authorization/registration) с логином и почтовым ящиком, делает требуемое подтверждение и проверяет восстановление доступа. Для второго адресата можно использовать другой изолированный командный тестовый ящик. Для демонстрации двух живых профилей подготовьте независимые привязки ящика и календаря.
2. Войдите в Почту, включите доступ почтовых клиентов по IMAP и создайте пароль приложения типа «Почта» в настройках безопасности Яндекс ID. Подключение приложения использует полный адрес ящика и пароль приложения. Тест отправки должен прийти в реальный второй тестовый ящик. [Настройка IMAP и пароля приложения](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others) · [Серверы и порты](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/ssl)
3. В Яндекс Календаре создайте отдельный календарь для стенда. Сгенерируйте отдельный пароль приложения типа «Календарь». Найдите календарь через CalDAV discovery и сохраните обнаруженный URL как конфигурацию профиля. Убедитесь, что это календарь, предназначенный для записи. [Настройка CalDAV](https://yandex.ru/support/yandex-360/customers/calendar/web/ru/data-exchange/synchronization/sync-desktop)
4. В Телемосте вручную создайте учебную комнату. Второй участник открывает ссылку со своего устройства. Доступ проверяете на обычном звонке уже до разработки. [Создание встречи в Телемосте](https://360.yandex.ru/blog/guides/kak-priglasit-uchastnikov-na-vstrechu-v-telemoste/)
5. Для облачных API создайте каталог в Yandex Cloud с действующим биллингом/доступом по правилам команды. Проверьте доступные регион и сервисы для фактического аккаунта. Создайте сервисный аккаунт с ролью `ai.languageModels.user` в каталоге и ключом с областью `yc.ai.foundationModels.execute`. Для речи выдайте отдельные учётные данные только с нужными ролями STT/TTS и соответствующими областями ключа по консоли. Сохраните идентификатор каталога и отдельно проверьте один вызов каждого API. Биллинг и доступ владельца к Cloud — отдельная проверка даже при рабочей почте. [Создание ключа и авторизация](https://aistudio.yandex.ru/ru/docs/ai-studio/api-ref/authentication) · [Роли SpeechKit](https://yandex.cloud/en/docs/iam/roles-reference)
6. Через `@BotFather` создайте отдельного Telegram-бота. Каждый тестовый пользователь начинает диалог с ботом командой `/start`. Владелец стенда вносит разрешённый Telegram ID пользователя и chat ID в настройки профиля по подтверждённому тестовому сообщению. Один токен одновременно опрашивает только один процесс. Для разработки Telegram владелец использует отдельный тестовый токен или согласованное окно опроса. [Инструкция Telegram по созданию бота](https://core.telegram.org/bots/tutorial) · [Bot API](https://core.telegram.org/bots/api)

Личный пароль от Яндекс ID и коды подтверждения остаются у владельца. Пароли приложений и ключи передавайте через защищённые настройки стенда. В `.env.example` храните имена параметров без значений. Отдельные переменные для `YANDEX_MAIL_APP_PASSWORD`, `YANDEX_CALENDAR_APP_PASSWORD`, `YANDEX_LLM_API_KEY`, `YANDEX_SPEECH_API_KEY`, `TELEGRAM_BOT_TOKEN`. Привязка профиля указывает имена или префиксы своего набора. При ревью не выводить секреты и содержимое писем.

## 2. Какие операции проверить с реального хоста

| API | Запрос и ожидаемый результат |
| --- | --- |
| IMAP | SSL 993, подключение к назначенному ящику, открыть Inbox read-only, увидеть UID контрольного письма и прочитать тело без изменения флага прочтения |
| SMTP | SSL 465, отправить короткое сообщение тестовому получателю, убедиться в фактической доставке. Сразу проверять с будущего хоста и сохранить вердикт по доступности исходящего порта |
| CalDAV | Найти коллекцию по discovery, прочитать окно тестовых дат, создать событие со стабильным UID, увидеть его в веб-календаре и прочитать обратно |
| Telegram | `getMe`, `getUpdates`, `sendMessage` с inline-кнопкой, `answerCallbackQuery`. Для polling убедиться, что у стендового бота нет активного webhook. Существующий чужой webhook не сбрасывать |
| AI Studio | `POST https://ai.api.cloud.yandex.net/v1/chat/completions`, заголовок `Authorization: Api-Key <key>`, модель `gpt://<folder_id>/yandexgpt-5.1`, `response_format.type=json_schema`. Получить и провалидировать объект. Для короткой реплики аватара получить обычный текст |
| SpeechKit | STT v3 `RecognizeStreaming` по gRPC, TTS v3 REST `/tts/v3/utteranceSynthesis`. Использовать параметры региона каталога, нужные заголовки и удостоверение сервисного аккаунта по документации. Проверить итоговую русскую реплику и воспроизводимый WAV |

[Структурированный запрос модели](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/completions-structured) · [Потоковое распознавание SpeechKit](https://aistudio.yandex.ru/en/docs/speechkit/stt/streaming) · [REST-синтез SpeechKit](https://aistudio.yandex.ru/ru/docs/speechkit/tts/api/tts-v3-rest)

Если авторизация работает локально, а исходящий SMTP или CalDAV недоступен на хосте, разберите хостинг в первый час. Протокол и правила могут разрабатываться с тестовыми адаптерами. Для живой сдачи перенесите сервис туда, где доступна реальная почта. Не выдавайте локальный smoke с фикстурами за подключение стенда.

## 3. С чего начать с аватаром

### 0–20 минут. Проверить аудио и видео без модели

1. На Windows-компьютере оператора запустите обычный клиент Телемоста или Яндекс Браузер. Войдите как «ИИ-помощник». Второй человек подключается с другого устройства и в наушниках. Участники знают, что голос будет обработан для учебного разговора.
2. Добавьте разрешённый образ в OBS. Первый вариант — лицо с двумя состояниями «слушает» / «говорит» и меткой «ИИ-помощник». Запустите Virtual Camera и выберите её в Телемосте. Попросите второго участника подтвердить видимость в сетке. Учётная запись и обычный вход используются для комнаты. Официальный REST API Телемоста документирует управление встречами, но в найденной документации нет пути для двустороннего медиаклиента бота. [Устройства Телемоста](https://yandex.ru/support/yandex-360/business/telemost/web/ru/call/access) · [OBS Virtual Camera](https://obsproject.com/kb/virtual-camera-guide) · [API Телемоста](https://yandex.ru/dev/yandex-360/telemost/ru/)
3. Для **входящего** звука выберите выделенный выход Телемоста, например наушники. Снимайте этот выход через Windows WASAPI loopback, например PyAudioWPatch, и отключите системные уведомления на тестовом компьютере. Запишите и прослушайте одну фразу собеседника. Loopback получает микс выбранного устройства, поэтому звук озвучки в него не направляют. [WASAPI loopback](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording) · [PyAudioWPatch](https://github.com/s0d3s/PyAudioWPatch)
4. Для **исходящего** звука проиграйте тестовый WAV непосредственно в устройство `CABLE Input`. В Телемосте выберите `CABLE Output` как микрофон. Это звуковой тракт отдельно от OBS. Второй участник подтверждает, что слышит WAV, а loopback не принимает исходящий файл за новую реплику. [VB-CABLE](https://vb-audio.com/Cable/)

### 20–45 минут. Включить живую реакцию

1. Загрузите фиксированный контекст предыдущего протокола. Первую синтетическую фразу озвучьте через TTS. В ответ второй человек говорит любую короткую фразу по вопросу, которой нет в сценарии.
2. Для первого прототипа оператор нажимает «Слушать» и «Стоп» в клиенте. Аудио привести к моно PCM16 и частоте, указанной в конфигурации распознавания. Передавать отрезок в SpeechKit v3, завершить вход и дождаться финального текста. Синтез и распознавание проверяются раздельно, затем совместно.
3. Передать финальный текст в HTTP-эндпоинт общего сервиса с ID сессии, номером реплики и устойчивым ID запроса. До появления сервиса проверить тот же контракт с тестовым адаптером. После подключения модель должна сформировать короткий русский ответ по смыслу новой фразы. Синтезировать его и проиграть через виртуальный микрофон. Сохранить обе текстовые реплики. При передаче TTS временно не открывать окно прослушивания, чтобы избежать обратной связи.
4. Засечь время от конца реплики до первого звука ответа и записать результаты нескольких попыток. Командная цель для проверки — 3–5 секунд при короткой фразе, её надо подтвердить замером. Для ускорения сначала сокращайте ожидание конца реплики и длину ответа. Если остаётся время, замените ручное окно звука определением конца реплики. LLM-ответ остаётся автоматическим.

### 45–60 минут. Довести до протокола и принять решение о площадке

1. Завершите встречу кнопкой клиента. Клиент дожидается подтверждения последней реплики через `/turns` и вызывает `/finish` с ID запроса. При завершении сервер использует уже сохранённые реплики, метки говорящих и контекст встречи. На стенде короткой демонстрации обеспечьте, чтобы в журнал попали все содержательные реплики обоих участников. Держите отдельный путь импортировать запись или готовую расшифровку в тот же формат, если часть беседы пропущена. Запись Телемоста можно получить как отдельный материал при поддержке клиента и с согласия участников. Конспект на отдельных тарифах в основу не закладываем. [Запись встречи](https://360.yandex.ru/blog/guides/kak-sdelat-zapis-vstrechi-v-telemoste/)
2. Зафиксируйте шесть наблюдений: образ виден, входящая фраза распознана, ответ получен по смыслу, ответ слышен удалённо, задержка измерена, текст дошёл до протокола или принят общим контрактом при готовом тестовом адаптере.
3. Если Телемост не даёт стабильного доступа к устройствам, проверьте ту же пару устройств в другой допустимой комнате, например МТС Линк при доступе. Если ни одна не прошла, развивайте протокол на учебном тексте, отмечая живую встречу как открытый блокер. Операторский вход и ручное окно прослушивания остаются явно описанными. Автономный вход и полнота разговора допроверяются перед защитой по требованиям организаторов.

**Тест первого часа можно проводить до готовности всей системы.** Нужны два компьютера или компьютер с телефоном, отдельная тестовая комната, аудио и видео устройства и один вызов речи. Для полного сквозного теста затем подключите все шаги из [карточки аватара](roles/04-avatar.md).
