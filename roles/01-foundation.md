## PR 1. Основа для остальных

1. Добавь `pyproject.toml`, пакет `app`, конфигурацию, `.env.example`, `.gitignore`, README, один `GET /health` и команды из общего контракта. Фиксируй проверенные версии зависимостей при первом совместном запуске.
2. Определи Pydantic-модели по разделу 3. Опубликуй реальные примеры формата без персональных данных. Используй один тип входящего письма, один тип версии и один тип результата эффекта. Исключения адаптера приводятся к общему результату.
3. Сделай миграцию SQLite и операции чтения/записи с областью профиля. `seed-demo` загружает два синтетических профиля с разными правилами и привязками. Повтор импорта обновляет заданную конфигурацию без перепривязки источников к чужому профилю. Приватный импорт не коммитить.
4. Добавь тестовые порты модели и внешнего транспорта, которые выдают заданный ответ или ошибку и протоколируют вызовы в тесте. `smoke` проходит регистрацию одного письма и создание одной версии. Отдай команде команды и примеры, чтобы их PR не ждали доступа к аккаунту.
5. Приёмка PR 1: новое виртуальное окружение, запуск по README, два профиля, чужой ID не читается, повтор входа не плодит событий, основной API готов для адаптеров.

## PR 2. Правила допуска и исполнение

1. Добавь обработчик сохранённых входов, `propose`, `revise_document` и `save_preference`. Сохраняй вход, версию, запрос согласования, журнал. Реализуй атомарный `decide` с проверкой актёра и версии, условной сменой статуса и созданием операций. Неполное поручение не запускается. Модель получает только сведения своего профиля.
2. Реализуй общий исполнитель внешних операций и алгоритм `pending/sending/sent/retryable/unknown/failed`. Для теста введи разовый сбой и потерю подтверждения. При рестарте очередь и курсор должны остаться. `retry-effect` повторяет только разрешённый эффект или принимает отдельно зафиксированное решение оператора после сверки неизвестного исхода.
3. Подключи Yandex AI Studio через httpx по документированному JSON-схеме. Валидируй JSON даже при структурированном запросе. Установи timeout и предел размера. При некорректном ответе классификация требует человека, протокол получает статус ошибки или черновик для проверки. Генерация реплики — отдельный быстрый вызов короткого текста. Логируй длительность, ID и код ошибки без текста и ключей.
4. Создай закрытую команду регистрации встречи и выдачи временного токена. Подключи модули почты, Telegram, встречи и workflow. Проверь реальную сеть с будущего хоста. Для пилота подними один worker с постоянным диском и HTTPS. Проверка вторым устройством плюс рестарт обязательны перед сдачей.

## Что передать и проверить

Передай версию контракта, список env-переменных, безопасные команды запуска и адрес тестового стенда. Автотесты должны покрыть чужой профиль, старую версию, два одновременных решения, частичный сбой, рестарт и неизвестный результат. Живые сообщения проверяйте совместно после подтверждения тестовых адресатов.

Передай владельцам живых каналов адрес и инструкцию, где увидеть результат тестового события. Если общий стенд задерживается, локальный запуск из README и синтетические адаптеры остаются способом интеграции. Назначьте владельца доступности стенда после сдачи и зафиксируйте, как поднять его по запросу.
